# F11.1 — Socle de déploiement : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rendre LeadFlow déployable en une commande — `docker compose -f docker-compose.prod.yml up -d` monte Postgres, RabbitMQ, le backend et un Nginx qui sert le dashboard et relaie l'API sous une origine unique.

**Architecture:** Une image `web` unique (Nginx sert l'Angular compilé et relaie `/api` vers `backend:8090`) devant une image backend multi-stage (JRE 21 au runtime). Sous une origine unique, CORS n'a plus d'objet : la configuration devient une propriété dont la valeur de production est la liste vide, et aucun `CorsConfigurationSource` n'est alors enregistré. La preuve est un script de fumée qui monte la pile réelle et traverse tout le pipeline.

**Tech Stack:** Docker multi-stage (`maven:3.9-eclipse-temurin-21`, `eclipse-temurin:21-jre-alpine`, `node:22-alpine`, `nginx:alpine`), Docker Compose, Spring Boot 4.1 / Java 21, Angular 20, Bash + `curl` + `openssl`.

**Spec:** `docs/superpowers/specs/2026-08-29-f11.1-socle-de-deploiement-design.md`

## Global Constraints

- **Le backend écoute sur `8090`**, jamais `8080`. À l'intérieur des conteneurs aussi.
- **Aucun secret en dur** nulle part : ni dans un YAML, ni dans un `Dockerfile`, ni dans le compose. Tout passe par des variables d'environnement.
- **`docs/` et les commentaires sont en français.** Les messages de commit sont en français **sans accents**, comme tout l'historique du dépôt.
- **Les sous-packages du backend sont des étapes du pipeline**, pas des couches. Toute nouvelle propriété typée va dans `com.leadflow.config` sous le préfixe `leadflow.*`, lue par un `record` `@ConfigurationProperties` — `@ConfigurationPropertiesScan` est actif, aucun enregistrement manuel.
- **`ddl-auto: validate`** : aucune migration Flyway dans cette session, le schéma ne bouge pas.
- **TDD sur tout le code Java** : test qui échoue, puis implémentation minimale.
- **Le daemon Docker doit tourner** pour `./mvnw test` (Testcontainers) comme pour toutes les tâches 3 à 7.
- **Après tout `npm test` ou `npm run build` local**, `git checkout -- frontend/angular.json` : l'Angular CLI y écrit un identifiant de télémétrie qui ne doit pas entrer dans un commit.
- **Branche de travail : `feature/f11.1-socle-de-deploiement`**, déjà créée, où la spec est déjà commitée (`578698d`).

```java
package com.leadflow.config;

import java.util.List;
import org.springframework.boot.context.properties.ConfigurationProperties;

/**
 * Origines autorisees a appeler l'API depuis un navigateur.
 *
 * <p>La liste est <b>vide en production</b>, et c'est le cas nominal : Nginx sert le
 * dashboard et relaie l'API sous une origine unique, donc il n'y a aucune requete
 * cross-origin a autoriser. Elle n'est peuplee qu'en developpement, ou ng serve tient le
 * :4200 pendant que le backend tient le :8090.
 *
 * <p>Un record separe de {@link SecurityProperties} plutot qu'un champ de plus : la cle
 * maitre et les origines n'ont ni la meme duree de vie ni le meme lecteur, et
 * SecurityProperties est instancie a la main par trois tests de chiffrement.
 */
@ConfigurationProperties(prefix = "leadflow.security.cors")
public record CorsProperties(List<String> allowedOrigins) {

    /** Jamais {@code null} : une propriete absente vaut une liste vide, pas une erreur. */
    public List<String> origines() {
        return allowedOrigins == null ? List.of() : allowedOrigins;
    }
}
```

```java
    @Bean
    SecurityFilterChain filterChain(HttpSecurity http, CorsProperties cors) throws Exception {
        return http
                .csrf(csrf -> csrf.disable())
                .cors(configurateur -> {
                    List<String> origines = cors.origines();
```

```java
        config.setAllowedOrigins(origines);
        config.setAllowedMethods(List.of("GET", "POST", "PUT", "PATCH", "DELETE", "OPTIONS"));
```

```dockerfile
# Etage 1 — build. Le pom est copie SEUL avant le source : la couche de dependances ne se
# reconstruit alors que si le pom change, ce qui fait la difference entre une minute et
# dix a chaque modification de code.
FROM maven:3.9-eclipse-temurin-21 AS build
WORKDIR /build
COPY pom.xml .
RUN mvn -B -q dependency:go-offline
COPY src ./src
# -DskipTests, et c'est delibere : ./mvnw test demarre des conteneurs Postgres et RabbitMQ
# par Testcontainers, or ce build tourne deja dans Docker. Construire l'image et eprouver
# le code sont deux gestes distincts — c'est la CI de F11.3 qui les enchainera.
RUN mvn -B -q package -DskipTests

# Etage 2 — runtime. Ni JDK, ni Maven, ni depot .m2 : seulement un JRE et le jar.
FROM eclipse-temurin:21-jre-alpine
RUN addgroup -S leadflow && adduser -S leadflow -G leadflow
WORKDIR /app
COPY --from=build /build/target/*.jar app.jar
USER leadflow
# 8090 et non 8080, dans le conteneur comme ailleurs : le port est une propriete du
# projet, pas une consequence du poste de developpement.
EXPOSE 8090
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;

    # Le flux temps reel. Ce bloc est un « location = », donc il l'emporte sur le prefixe
    # /api/ quelle que soit sa position dans le fichier. Sans proxy_buffering off, nginx
    # accumule le flux SSE et le dashboard se fige : le battement part toutes les 20 s et
    # l'emetteur expire a 30 min, deux valeurs portees par application.yml.
    location = /api/stream/leads {
        proxy_pass http://backend:8090;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
        # Pour un eventuel proxy place devant celui-ci : lui dire de ne pas tamponner non
        # plus. Sans effet sur nginx lui-meme, qui obeit a proxy_buffering ci-dessus.
        add_header X-Accel-Buffering no;
    }

    # L'API, webhooks compris. C'est ce bloc qui fait disparaitre CORS : le navigateur ne
    # voit qu'une seule origine.
    location /api/ {
        proxy_pass http://backend:8090;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    # La sante, pour les sondes exterieures. Le reste d'actuator n'est pas expose.
    location = /actuator/health {
        proxy_pass http://backend:8090;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # index.html porte les noms hashes des chunks : le mettre en cache figerait
    # l'application sur une version disparue au deploiement suivant.
    location = /index.html {
        add_header Cache-Control "no-cache";
    }

    # Les chunks portent un hash dans leur nom : leur contenu ne change jamais.
    location ~* \.(?:js|css|woff2?|png|jpe?g|svg|ico)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # Routage cote client : /leads/42 n'existe pas sur le disque, il faut rendre l'index.
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

```bash
BASE="${BASE:-http://localhost}"

[ "${1:-}" = "--keep" ] && GARDER=1

etape() { printf '\n== %s\n' "$1"; }
echoue() { printf '\n!! ECHEC : %s\n' "$1" >&2; exit 1; }

nettoie() {

    printf '\nPile laissee debout (--keep). La demonter : %s down -v\n' "$COMPOSE"
  else
    $COMPOSE down -v >/dev/null 2>&1 || true

etape "0. Prerequis"
[ -f .env.prod ] || echoue ".env.prod absent — le creer depuis .env.prod.example"
command -v openssl >/dev/null || echoue "openssl introuvable"

MOT_DE_PASSE="${SMOKE_PASSWORD:-}"
[ -n "$MOT_DE_PASSE" ] || echoue \
  "SMOKE_PASSWORD non defini — donner le mot de passe en clair de LEADFLOW_ADMIN_PASSWORD_HASH"

$COMPOSE up -d --build

etape "2. Attente de la sante (jusqu'a 240 s)"

# sain et le backend migre ensuite. Un sleep fixe rendrait ce script vert ou rouge selon
# la charge de la machine.
for i in $(seq 1 120); do

    printf 'sain apres %s s\n' "$((i * 2))"
    break
  fi

  sleep 2
done

[ "$code" = "200" ] || echoue "GET / rend $code, attendu 200"

[ "$code" = "200" ] || echoue "GET /leads/42 rend $code, attendu 200 (try_files absent ?)"

[ "$code" = "401" ] || echoue "GET /api/leads sans jeton rend $code, attendu 401"

  -H 'Content-Type: application/json' \
  -d "{\"username\":\"$UTILISATEUR\",\"password\":\"$MOT_DE_PASSE\"}" \

etape "6. Creation d'une boutique par l'API"
# Une base de production demarre vide : db/dev n'est jamais charge. L'amorcage passe par
# l'API, jamais par du SQL. baseUrl pointe volontairement dans le vide — la synchronisation
# ERP n'est pas ce que ce script eprouve.

  -H "Authorization: Bearer $JETON" \

       "crmProviderId":"dolibarr",
       "assignmentStrategy":"ROUND_ROBIN",
       "crmSettings":{"baseUrl":"http://injoignable.invalid/api/index.php",
                      "apiKey":"cle-de-fumee"},

                        "email":"commercial@example.test"}}')

  -H 'Content-Type: application/json' \
  -H "X-Leadflow-Signature: t=$T,v1=$V1" \
  -d "$CORPS")
code=$(printf '%s' "$reponse" | tail -1)
EVENT_ID=$(printf '%s' "$reponse" | head -1 | sed -n 's/.*"eventId":"\([^"]*\)".*/\1/p')
[ "$code" = "202" ] || echoue "le webhook rend $code, attendu 202"

etape "8. Rejeu : meme signature, meme eventId"
reponse=$(curl -s -X POST "$BASE/api/webhooks/leads/$CLE_PUBLIQUE" \
  -H 'Content-Type: application/json' \
  -H "X-Leadflow-Signature: t=$T,v1=$V1" \
  -d "$CORPS")
REJEU=$(printf '%s' "$reponse" | sed -n 's/.*"eventId":"\([^"]*\)".*/\1/p')
[ "$REJEU" = "$EVENT_ID" ] || echoue "le rejeu rend $REJEU au lieu de $EVENT_ID"

etape "9. Le lead traverse le pipeline (jusqu'a 60 s)"
for i in $(seq 1 30); do
  if curl -fsS "$BASE/api/leads?clientId=$CLIENT_ID" \
       -H "Authorization: Bearer $JETON" | grep -q "$EMAIL"; then
    printf 'lead visible apres %s s\n' "$((i * 2))"
    break
  fi
  [ "$i" -eq 30 ] && echoue "le lead n'est pas apparu en 60 s ($COMPOSE logs backend)"
  sleep 2
done

etape "10. Le flux SSE n'est pas tamponne par nginx"
# Le battement part toutes les 20 s. Si proxy_buffering est actif, nginx accumule et rien
# n'arrive : la sortie est vide et le script echoue. C'est le seul point que rien d'autre
# ne peut prouver.
BATTEMENT=$(curl -sN --max-time 30 "$BASE/api/stream/leads" \
  -H "Authorization: Bearer $JETON" | head -c 64 || true)
[ -n "$BATTEMENT" ] || echoue "aucun octet recu du flux SSE en 30 s — proxy_buffering off absent ?"

printf '\n== Tout est vert.\n'
```
