## Les arbitrages pris, et ce qu'ils coûtent s'ils sont faux

**Ruling 1 — toute invocation de `docker compose -f docker-compose.prod.yml` porte
`--env-file .env.prod`.** Le plan comptait sur `env_file: .env.prod` pour alimenter aussi
l'interpolation `${POSTGRES_PASSWORD:?...}` du YAML. C'est faux : `env_file` fournit des
variables **au conteneur**, tandis que `${...}` est interpolé **à la lecture du fichier**,
depuis le shell ou `.env` — jamais depuis `.env.prod`. Sans correction, `up -d` échouerait dès
la première commande. Touche les tâches 6, 7 et 8. *Coût si erreur : nul, la commande est
seulement plus longue.*

**Ruling 2 — le compose de production utilise `rabbitmq:3-management-alpine`**, comme celui de
développement, sans publier le port 15672. Le plan proposait `rabbitmq:3-alpine`, dont
l'existence n'est pas vérifiée, alors que `CLAUDE.md` demande des images alignées. L'objectif —
ne pas exposer la console — est atteint en ne publiant aucun port. *Coût si erreur : quelques
mégaoctets d'image en trop.*

**Ruling 3 — le test de la tâche 1 devait verrouiller la décision d'architecture.** La revue a
montré que `CorsVideTest`, tel que mon plan l'écrivait, serait resté vert si quelqu'un avait
enregistré une source CORS avec une liste **vide** au lieu de n'en enregistrer aucune : les
deux implémentations rendent le même en-tête absent. J'ai tranché pour une assertion
supplémentaire. *Coût si erreur : une assertion de plus dans un test.*

**Et une correction de cet arbitrage, venue de l'agent.** J'avais dicté d'asserter l'absence de
bean `CorsConfigurationSource` : c'était faux, `mvcHandlerMappingIntrospector` étant un bean de
ce type publié par Spring MVC indépendamment de nous. L'agent a asserté l'absence de
`CorsFilter` dans la chaîne de filtres — le bon discriminant — et l'a prouvé par une mutation
délibérée de `SecurityConfig`, restaurée ensuite. Retenir la méthode : **une assertion qui ne
peut pas échouer ne prouve rien**.

## Ce qu'il faut savoir pour la prochaine session

**Les agents s'arrêtent au lieu d'attendre.** Trois fois, un agent lancé sur `./mvnw test` a
rendu la main en disant « j'attends la fin du run », parce qu'il attendait par un `Monitor` ou
une tâche de fond. Les relancer en leur imposant **une seule commande Bash bloquante avec
`timeout: 900000`** a résolu le problème à chaque fois. Le mettre dans le dispatch dès le
départ.

**`./mvnw test -Dtest=A+B` est rejeté par Surefire dans ce shell**, contrairement à ce
qu'annonce `CLAUDE.md` ; la forme `-Dtest=A,B` fonctionne. La suite complète prend de quinze à
vingt-cinq minutes.
