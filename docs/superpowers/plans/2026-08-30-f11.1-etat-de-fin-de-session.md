### Pourquoi la suite ne va pas à son terme

**La machine manque de mémoire, et rien d'autre.** Le symptôme final est
`./mvnw: fork: retry: Resource temporarily unavailable` : Maven ne peut plus créer de
processus. Mesuré pendant la session : **0,42 Go libre sur 7,87 Go**.

Trois consommateurs, dans l'ordre : le moteur Docker (`vmmem`, 1,9 Go, qu'il ne rend pas
même sans conteneur), le navigateur (1,2 Go), et les processus Surefire laissés par les runs
précédemment interrompus.

**Le cercle vicieux à connaître :** chaque run tué laisse derrière lui ses Testcontainers et
son processus Surefire, qui saturent un peu plus la machine et font tuer le suivant. Il a
fallu supprimer **51 puis 35 conteneurs orphelins** et quatre processus java pour récupérer
environ 1 Go.

### Comment reprendre demain

Avant toute chose, faire de la place : fermer le navigateur, et vérifier qu'aucun orphelin
ne traîne.

```bash
docker ps -aq --filter "label=org.testcontainers=true" | wc -l     # doit rendre 0
docker rm -f $(docker ps -aq --filter "label=org.testcontainers=true")   # si ce n'est pas 0
```

Puis rejouer la suite **par lots**, jamais d'un bloc — un run complet dure quinze à
vingt-cinq minutes et n'a pas survécu une seule fois :

```bash
./mvnw test -Dtest='com.leadflow.tenant.*Test'
./mvnw test -Dtest='com.leadflow.routing.*Test'
./mvnw test -Dtest='LeadQualificationIntegrationTest,LeadQualificationListenerTest,LeadReferenceTest,QualificationModeDegradeTest,QualifiedLeadRelayTest'
```

Rediriger chaque lot vers un fichier (`> lot.log 2>&1`) : sans cela, une interruption ne
laisse rien à lire, et le diagnostic est à refaire. La forme `-Dtest=A+B` est rejetée par
Surefire dans ce shell ; `-Dtest=A,B` fonctionne.

Une fois tous les lots verts :

```bash
git push origin main
git push origin feature/f11.1-socle-de-deploiement
```

production par `docker network connect`, ce qui est à refaire après chaque remontée si une
